## 2. 批次划分原则（A↔D 不冲突下的务实策略）

1. **按文件夹分批**：162 文件夹 → 建议 30–40 个批次（每批 ≈ 1000–1300 条 job_set，取整到场景块）。
2. **类型优先**：每批内先 `seedance_2_0`（视频，占 89%）再图像；长 prompt 单独建"长提示批次"（>20k 字符，抽样复用 `badbd6b7` 模板）。
3. **L1 字面 vs L3 对照**：技术底座/硬约束（L1）优先保强度逐字；镜头叙事（L3）用"忠实+注释"。均走词表 v0.1。
4. **与 NAS 同步/862G 无依赖**：汉化是纯文案+并排 `.zh.md`，不依赖媒体 blob → **可与同步完全并行**，是"等媒体"期间的最佳推进。

## 4. 每批流程（复用试点通过的标准）

```
1. inventory：列该夹全部 prompts/*.txt（不含 Assets）
2. 直译 → 并排 `.zh.md`（译/校分离；draft）
3. 校对：零 S0（硬禁令/原文块/id）/ 零 S1（词表冲突/因果译反/标签翻译）
4. 抽检样本（见 `04-质检/抽检记录模板.md`）
5. 通过 → 记入 `07-对照索引/alignment.jsonl` (status=reviewed, glossary_ver=v0.1)
6. 提交（`git add` 该夹的 `.zh.md`，经 `scripts/add_zh_md_to_git.sh` 入库）
```

## 5. 质量闸门（跨批复用）

- **词表**：v0.1 冻结；新概念 → `proposed` → 评审 → v0.2 变更，记 `受控词表` 变更记录，不静默。
- **原文铁律**：绝不改 `.txt`/官方 JSON 语义；`.zh.md` 与源 `prompts/*.txt` 冲突时以源为准。
- **溯源**：每条 `.zh.md` 带 `source_path/job_set_id/job_type`（模板见 `00-治理/并排双语落盘规范.md` §4）。
- **回滚**：批内降级 `approved→draft` 重跑，不覆盖仓根原文。
