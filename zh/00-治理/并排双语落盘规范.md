# 并排双语落盘规范（最高优先级）

> **每一个视频生成任务**的源 prompt / 设计说明旁，必须有一份汉化文档。  
> **不是**另建一套中文目录树；**源仓 `folders/` 结构仍按原计划**。

---

## 1. 原则

| 原则 | 说明 |
|------|------|
| **源结构不变** | `folders/<官方名>/`、`prompts/`、`Assets/`、`job_sets.json` 等**原计划路径与命名**不变 |
| **原文不覆盖** | 禁止用中文覆盖 `.txt` / 官方 JSON 中的 `params.prompt` 原文 |
| **旁路并排** | 汉化以**同目录旁路文件**存在，与源文件一一对应、可一眼看见 |
| **可回溯** | 汉化文件内写明 `source_path`、`job_set_id`、`job_type` |

---

## 2. 源仓结构（保持原计划）

```text
folders/
  Hell Grind/
    Scene 26/
      folder.json
      job_sets.json
      media_manifest.json
      summary.json
      prompts/
        00001_9691ba91-….txt          ← 源 prompt（原文，勿改）
        00001_9691ba91-….json         ← 源元数据（勿改语义字段）
        00001_9691ba91-….zh.md        ← 汉化对照（新增，并排）
        00002_….txt
        00002_….zh.md
        …
      Assets/                         ← 媒体仍按原计划（blob 硬链）
        outputs/ thumbnails/ references/
```

Brief 等同理：

```text
brief/
  PROJECT_BRIEF.md                    ← 原文
  PROJECT_BRIEF.zh.md                 ← 汉化对照（并排）
  project-brief.raw.txt               ← 原文
  project-brief.raw.zh.md             ← 可选对照
```

---

## 3. 命名约定（强制）

| 源文件 | 并排汉化文件 |
|--------|----------------|
| `foo.txt` | `foo.zh.md` |
| `foo.md` | `foo.zh.md` |
| `00002_<job_set_id>.txt` | `00002_<job_set_id>.zh.md` |
| `ALL_PROMPTS.txt` | `ALL_PROMPTS.zh.md`（可选汇总；**不能替代**逐条 `.zh.md`） |
| `summary.json` | `summary.zh.md`（人类可读摘要的中文；不改 JSON） |
| 无扩展名 | `<name>.zh.md` |

- 扩展名统一 **`.zh.md`**（Markdown 对照文档）。  
- **禁止**改官方文件夹显示名；**禁止** `Scene 26 (中文)` 类目录。  
- **禁止**把全量译文只放在 `zh/content/folders/...` 而源旁无文件（`zh/content` 仅可选镜像/工具输出，**不能替代并排**）。

---

## 4. 单条 prompt 对照文件模板

文件名示例：`prompts/00002_15e958ff-0c1a-4c01-845d-59a085c64548.zh.md`

```markdown
# prompt 对照

## 元数据
- job_set_id: 15e958ff-0c1a-4c01-845d-59a085c64548
- job_type: seedance_2_0
- source_path: folders/Hell Grind/Scene 26/prompts/00002_15e958ff-0c1a-4c01-845d-59a085c64548.txt
- folder_official_name: Scene 26
- translation_status: draft | reviewed | approved
- glossary_version: v0.1

## 原文 (source)

（全文粘贴或与 .txt 保持一致；校对时以 .txt 为准）

## 中文对照 (zh)

（全文中文）

## 备注（可选）
- 术语：…
```

规则：

- **不得**删除或只保留中文块。  
- 正文以同目录 `.txt` 为权威原文；`.zh.md` 内「原文」块可与之同步，冲突时以 `.txt` 为准。

---

## 5. 视频生成任务覆盖范围

对每个含生成任务的场次文件夹，**至少**保证：

1. `prompts/` 下**每一条**有效源 prompt 文本（`.txt` 或官方导出的正文文件）旁有 `.zh.md`  
2. 若存在场次级设计说明（如 `summary` 人类摘要、设计笔记 md），并排 `.zh.md`  
3. 项目级 `brief/*` 说明文档并排 `.zh.md`  
4. 技能文件（若取得）并排 `.zh.md`

`job_sets.json` **不翻译键名**；需要批注时用旁路 `job_sets.notes.zh.md`（可选），**禁止**改写 JSON 官方字段值冒充原文。

---

## 6. `zh/` 目录还做什么？

`zh/` **不是**第二套场次树，而是：

| 内容 | 路径 |
|------|------|
| 治理 / 术语 / 流程 / 质检 | `zh/00-` … `zh/07-` |
| 词表、抽检记录、进度 | `zh/01-术语表`、`zh/06-全量作业` |
| 对照索引、链接清单 | `zh/07-对照索引` |
| 可选工具输出 | `zh/content/`（**不得**替代并排 `.zh.md`） |

---

## 7. 完成判据（场次级）

某场次「汉化旁路完成」当且仅当：

- [ ] 该场 `prompts/` 中每个应对齐的源文本文件均存在同 stem 的 `.zh.md`  
- [ ] 每个 `.zh.md` 含元数据 + 原文块 + 中文块  
- [ ] `translation_status` 已标 `draft|reviewed|approved`  
- [ ] 未修改任何源 `.txt` / 官方 JSON 语义字段  

全量：所有含 job 的场次满足上列 + Brief 并排完成。

---

## 8. 与 know-how

- 取证：读源 `.txt` / `job_sets.json`  
- 定稿中文：优先读**同目录** `.zh.md` 的「中文对照」  
- 无 `.zh.md` 时标 `[临时译]`，并回写并排文件后再定稿
